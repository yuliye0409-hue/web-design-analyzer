    THE STANDARD OPERATING PROCEDURE

    完整使用流程

    把分析当作“采集证据—人工判断—明确交付”的过程，不要跳过校对。

    01—06
    01
    准备参考与目标

    先说清楚要研究什么

    进入「网页分析」，填入无需登录即可访问的公开网址，选择最终要制作的页面类型，并补充目标用户、页面目标、期望色调、设备范围及你在浏览时观察到的细节。

    • 优先选一个结构完整、能公开访问的具体页面。
    • 写下你希望借鉴的布局/氛围，也写明不想照搬的内容。
    • 网址会交给当前分析服务访问；勿提交内网、登录页或含敏感信息的链接。
    去网页分析 ↗
    02
    发起真实采集

    实采证据不是设计结论

    点击「实际分析参考网页」，等待状态反馈。成功时可查看桌面/手机截图和采集到的区块、文字、链接、图片、控件等信息；若目标站不可达，先检查网址或换一个公开页面。

    • 工具不登录目标站、不提交表单或购买；会滚动页面、悬停候选控件，并有限点击手风琴/标签等安全、可恢复控件，记录观察到的状态变化。
    • 采集不覆盖所有动画或隐藏状态；未记录变化、受限制或危险的交互需手动补充，不得写成已实测。
    • 截图和可见元素是证据；审美判断、转化原因仍需你核对。
    03
    编辑独立分析工作区

    逐模块核对并补全

    检查每张模块卡片的“页面目的、风格与排版、组件与信息层级、动效与交互、专业判断”。将事实和推断分开；可直接改字、添加缺失模块、删除不适用模块，并用上下箭头调整页面顺序。

    • 点「恢复建议模块」可回到该页面类型的默认提纲。
    • 点击任一输入即可修改；分析会自动保存到当前浏览器。
    • 不要把自动采集不到的动效写成已验证事实。
    回到模块分析 ↗
    04
    添加自己的内容与设计规则

    让生成结果属于你

    进入「提示词工作台」，粘贴真实简历、公司、品牌、产品和项目事实；上传图片或附件并注明用途。需要 Agent 使用的素材请下载到 Agent 能访问的项目目录。再到「DESIGN.md 设计系统」选择 Apple、Claude 或 Vercel 规范并从 GitHub 加载，或上传/粘贴自己的 Markdown；可在文本区直接编辑后导出 DESIGN.md。

    • 选中的设计系统会自动加入生成提示词，作为可选视觉建议；网页实采事实、用户明确要求优先，不能把文档建议冒充参考站真实效果。
    • 远程加载需要网络；失败时可从 GitHub 下载原文件后上传。设计规范和文字草稿保存在当前浏览器，不会自动跨设备同步。
    • PDF/DOCX 附件不会自动提取全文；重要事实请复制到资料框。只填写已确认信息，不要上传机密或未授权文件。
    添加资料与设计系统 ↗
    05
    选择交付模式并生成

    按 Agent 的任务选择模式

    「分析并搭建」让 Agent 再次检查参考页并实现；「按现有分析搭建」使用你编辑好的模块；「只分析网页」只交付报告。填写 Agent 名称、现有技术栈和必须遵守的限制，再生成可编辑提示词。

    • 复制提示词到 Codex、Gemini、Claude Code 等 Agent，或导出 Markdown 文件。
    • 上传素材需与 Agent 项目一并提供；提示词会说明用途，不会嵌入图片二进制。
    • 提示词生成后仍可手动修改，交付前检查目标、内容事实和组件可编辑要求。
    打开提示词工作台 ↗
    06
    复盘、学习与迭代

    把作品转化成设计方法

    生成网页后，对照原分析检查模块是否齐全、交互是否真实可用、手机布局是否合理。回到分析区或提示词中修订，再让 Agent 迭代；在「设计知识」学习如何把主观偏好写成可观察、可验证的要求。

    • 将“我想要有质感”改写为字体、留白、对比、材质和反馈等具体线索。
    • 指出具体屏幕、组件、触发方式和预期结果，Agent 更容易执行。
    • 逐轮验证，不要只凭首屏截图验收长页和移动端体验。
    学习设计知识 ↗
    LEARN WHILE BUILDING

    用专业方法读懂网页

    分析不是“描述好不好看”，而是说明页面如何帮助特定用户完成任务。每个模块都可以按下面的框架练习。

    观察事实页面实际出现了什么？

    位置、文字、色彩、图片比例、按钮、断点和真实可见状态。

    解释目的为什么这样组织内容？

    判断它服务的用户任务、内容优先级、信任建立或转化目标。

    提出建议哪些原则可以迁移？

    总结可复用的版式/组件规律，为新品牌重做内容与视觉，而不是照搬素材。

    TROUBLESHOOTING

    常见问题与边界

    先区分“网页界面可以打开”和“本地分析服务可用”是两个不同状态。

    为什么 GitHub Pages 上能打开页面，却分析不了新网址？

    GitHub Pages 只托管静态界面，不运行这个项目所需的 Node.js + Chromium 分析接口。临时实采可在电脑上安装 Node.js、依赖和 Chromium 后运行 npm start，访问 http://127.0.0.1:4173/；想让所有访客在线实采，需要把项目部署为 Docker Web 服务，让网页与 /api/analyze 同源运行。查看容器部署步骤 ↗。部署对外服务前应配置请求限频、并发和网络出口限制。

    为什么有的参考网站分析失败或结果不完整？

    站点可能不可访问、要求登录、阻止自动化浏览器、需要特殊地区/脚本或加载时间较长。不要绕过登录或访问限制；改用公开页面，并把无法观察的细节标注为未知或人工观察。采集器不会操作目标站点的表单和菜单。

    自动分析为什么没有说清楚动画和点击效果？

    自动采集侧重可见页面结构和样式，不会全面触发交互。手动悬停、点击、滚动目标网站后，将触发条件、动效方向/节奏和状态变化补充到「整体视觉与动效观察」或对应模块。

    为什么我上传的图片/资料没有出现在 Agent 生成的网站里？

    素材保存在你当前浏览器的本地资料库，提示词会列出文件用途，但不会把二进制内容传给任意 Agent。请在提示词工作台下载需要的文件，并放进 Agent 可访问的项目目录。跨设备时也要单独转移素材；不要上传机密或未经授权的图片。

    更换电脑后分析和上传资料会自动同步吗？

    不会。界面设置保存在浏览器本机，上传文件保存在该浏览器的 IndexedDB；它们不是 GitHub 仓库内容。需要跨设备继续时请导出提示词并转移素材，或者在新电脑重新输入/载入分析。

    FOR TEAMS / NEW COMPUTER

    在另一台电脑继续使用

    代码和 SOP 在 GitHub；本地 Node 分析服务、浏览器草稿和素材是分开的。每台需要实采的电脑都要单独完成一次环境安装。

    1. 安装 Git 与 Node.js 20 或更新版本。
    2. 克隆仓库 git clone https://github.com/yuliye0409-hue/web-design-analyzer.git，进入项目目录。
    3. 运行 npm install，首次额外运行 npm run browser:install；Windows 下载失败时，服务会自动使用已安装的 Chrome/Edge。
    4. 执行 npm start，访问 http://127.0.0.1:4173/ 完成实采。
    5. 协作修改前先拉取最新代码；完成后提交并推送。切勿提交个人资料、参考网页截图或本地环境密钥。

    WORKFLOW / GUIDE

    分析公开网页并保留证据。

    提交网址后，分析服务会在隔离的无登录浏览器中加载页面，采集桌面和手机截图、可见标题、区块、链接、图片与控件。网站本身不会收到你的登录凭据。

    当前分析由浏览器实测与本地规则生成，不调用云端大模型。自动化不会点击或提交目标站点控件；菜单反馈、滚动动画等隐藏状态需要你手动补充。无法访问或受到限制的网站会显示错误，不伪造分析结果。

    分析模块可以编辑、添加、排序。复制或导出的提示词会包含采集信息和验证边界。
